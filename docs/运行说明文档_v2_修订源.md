# CRN 项目运行说明（S3 场景）

本文按“配置环境 → 准备数据 → 检查 → 训练 → 评估”说明完整流程。所有命令均在 Linux/WSL2 Ubuntu 终端、项目根目录执行；不要在 Windows PowerShell 中运行。

## 1. 配置运行环境

### 1.1 目标电脑需要准备什么

- 64 位 Linux 或 WSL2 Ubuntu，以及 Miniconda/Anaconda。离线包不包含 Conda 安装程序；完全离线的电脑需预先取得并安装它。
- NVIDIA GPU 和可用驱动。运行 `nvidia-smi` 应能看到 GPU；WSL 用户还需确认 WSL GPU 透传正常。
- 编译工具：GCC/G++、CUDA Toolkit（含 `nvcc`）、CMake、Ninja。交付包不含本机编译的自定义 CUDA `.so`，因此目标机需要编译；CUDA Toolkit 应与所装 PyTorch CUDA 版本兼容。
- 项目目录及 `offline_bundle_rtx4000_cu117/` 整体复制到目标电脑，不能只复制源码而漏掉离线包。

本离线包固定为 Linux x86_64、Python 3.10、PyTorch 2.0.1+cu117、torchvision 0.15.2+cu117，项目依赖包括 mmcv-full 1.7.0、mmdet 2.25.2、mmsegmentation 0.30.0 和 NumPy 1.26.4。它是为 CUDA 11.7 的 RTX 4000 目标组合准备的，不是所有 GPU/驱动组合的通用环境；尚需在接收方的具体显卡上完成编译和冒烟验收。

### 1.2 使用随项目提供的离线包（推荐）

```bash
cd /path/to/CRN_TEST_delivery
ENV_NAME=CRN_50 bash scripts/install_offline_bundle.sh ./offline_bundle_rtx4000_cu117
```

安装脚本会创建并激活 Python 3.10 环境，离线安装 Torch 和 Python 依赖，尝试编译 CRN 自定义算子，最后运行安装检查。完成后，在新的终端中执行：

```bash
conda activate CRN_50
cd /path/to/CRN_TEST_delivery
export PYTHONPATH="$PWD:$PWD/third_party/mmdetection3d:${PYTHONPATH:-}"
python scripts/check_installation.py
python scripts/check_scene_interface.py
```

成功标志：安装检查显示 `cuda_available=True` 和 `CRN S3 portable installation: PASS`；场景检查显示 `Dynamic scene interface calculations: PASS`。若失败，先记录日志中第一条实际 `error`，不要只看最后的 `ninja failed` 或 pip 汇总提示。

`setup_environment.sh` 是需要联网的便捷安装脚本，不是离线安装器。它的 GPU 模式默认安装 CUDA 12.8 索引中的 PyTorch，不能替代上面的固定 cu117 组合；不要在同一环境里混用两种安装流程。若目标电脑不是该离线包对应的平台/显卡组合，应先确认 Torch、torchvision、MMCV 与 CUDA 编译器兼容，再配置新环境。

## 2. 准备原始数据

每个有效帧需要一组能够对应上的数据：一帧图片、一份 JSON 车辆标注，以及 CSV 中属于该帧的雷达记录。帧号或文件名映射必须正确。

```text
data/
├── radar/scene.csv
├── images/                 # 例如 112.png、113.png……
└── jsons/                  # 例如 112.json、113.json……
```

雷达 CSV 默认列为 `Frame, Range, Angle, Speed, SNR`。列名不同可在场景配置中映射。雷达数据不需要人工目标标签；目标类别、中心、尺寸和航向角来自逐帧 JSON 标注。

JSON 至少要满足当前预处理器的数据约定：相机内参 `fx/fy/cx/cy`、图像原始宽高、世界到相机的 4×4 外参，以及 `objects` 中每个车辆的类别、中心 `translation`、尺寸 `size=[长,宽,高]` 和航向角 `rotation`。坐标系、角度单位、平移是车辆接地点还是几何中心，必须与项目约定一致。不要把 S3 示例中的标定数值直接当作新场景实测值。

## 3. 创建场景配置

从模板复制一份独立配置：

```bash
cp configs/scene_template.json configs/scene_my_scene.json
```

编辑新文件，至少核对：

- `scene_id`、`inputs`：场景名、雷达 CSV、图片目录、标注目录，以及帧号/文件名/CSV 列映射。
- `output`：本场景独立的预处理目录、info pkl 名称和训练输出目录。
- `calibration.camera`：真实内参、原始图像宽高、`world_to_camera_4x4`。
- `calibration.radar`：雷达离地高度、道路坐标系中的 XY 位置和 yaw；同时确认 CSV 的 range、水平角、角度方向/单位和径向速度定义与预处理假设一致。
- `bev` 与 `model`：BEV 范围覆盖全部目标，网格尺寸满足道路定位精度需求；输入尺寸和深度范围覆盖实际图像及目标距离。程序会据此计算网格形状、FPN 和深度通道，但不会替你决定道路范围或标定值。
- `dataset_split`：默认按帧顺序 70%/20%/10% 划分 train/val/test，不随机打乱。保持验证集和测试集独立，避免用 test 反复调参。
- `training`、`evaluation`：训练轮数、batch size、学习率、验证开关、阈值和可视化设置。

配置中的相对路径以该 JSON 文件所在目录为基准。S3M 示例可参考 `configs/scene_s3m_example.json`；它只适合作为格式示例，不代表新场景标定。

## 4. 检查并生成训练数据

先验证路径、标定和可计算的模型几何，再查看实际计算结果：

```bash
python -u scripts/crn_scene.py validate --config configs/scene_my_scene.json
python -u scripts/crn_scene.py inspect  --config configs/scene_my_scene.json
```

抽几帧检查真值框和雷达投影：

```bash
python -u scripts/crn_scene.py preview \
  --config configs/scene_my_scene.json --max-frames 5
```

先做两帧 dry-run（不写训练数据），通过后生成全量数据：

```bash
python -u scripts/crn_scene.py prepare \
  --config configs/scene_my_scene.json --dry-run --max-frames 2
python -u scripts/crn_scene.py prepare --config configs/scene_my_scene.json
```

预处理会生成雷达 BEV/PV 特征、由雷达投影得到的稀疏深度、info pkl 和数据清单。稀疏深度不等于稠密深度真值。使用 SNR 时，`normalization: auto_train` 会仅用训练集统计均值和标准差，验证/测试集复用该统计量。

只要改了输入帧映射、标定、雷达几何、BEV/图像/深度范围或数据集划分，就重新执行 prepare。只改训练轮数、学习率或评估阈值时无需重新预处理。

## 5. 冒烟测试与训练

先验证 dataloader 和真实配置的一次模型前向：

```bash
python -u scripts/crn_scene.py smoke \
  --config configs/scene_my_scene.json --forward
```

确认通过后，最小训练测试（3 轮、每轮 1 个 batch）：

```bash
python -u scripts/crn_scene.py train \
  --config configs/scene_my_scene.json --epochs 3 \
  --limit-train-batches 1 --output-dir outputs/smoke_train
```

正式训练按 JSON 的 `training` 设置执行：

```bash
python -u scripts/crn_scene.py train --config configs/scene_my_scene.json
```

`training.init_checkpoint: null` 表示从头训练；填写兼容 checkpoint 表示用它初始化模型参数。若要从中断处完整续训（包括 epoch、优化器和学习率调度器状态），使用 `--resume`，不要把它与初始化权重混为一谈：

交付包自带的 S3 初始化权重为 `pretrained/s3_full_512h_epoch23_step13392.ckpt`。S3 示例配置已指向该权重；新场景如需微调，可复制下列有效 JSON 值到配置。若从头训练则保留 `null`。JSON 不支持 `//` 注释，不能把带注释的内容直接放进配置文件。

```json
"init_checkpoint": "../pretrained/s3_full_512h_epoch23_step13392.ckpt"
```

```bash
python -u scripts/crn_scene.py train \
  --config configs/scene_my_scene.json \
  --resume /path/to/last.ckpt --additional-epochs 50
```

训练期间的验证由 `validate_during_training` 控制，`validation_every_n_epochs` 设置间隔。训练日志中的 val loss 不等同于 MOTA/ATE；这些检测/跟踪指标仍需运行独立评估。

## 6. 评估、结果与可视化

调参时使用验证集；最终报告使用测试集：

```bash
python -u scripts/crn_scene.py evaluate \
  --config configs/scene_my_scene.json \
  --ckpt /path/to/checkpoint.ckpt --split val \
  --out-dir outputs/my_scene/val

python -u scripts/crn_scene.py evaluate \
  --config configs/scene_my_scene.json \
  --ckpt /path/to/checkpoint.ckpt --split test \
  --out-dir outputs/my_scene/test
```

评估器会调用 `third_party/TNsMultiTrackAdaptive` 跟踪模块。输出目录包含检测指标 `metrics.json`、跟踪指标 `tracking_metrics.json`、预测 CSV、`tracking_states.csv` 和逐帧可视化（红色 GT、绿色 TP、品红色 FP）。视频和纵向偏差图由独立脚本生成；先看脚本顶部的输入/输出路径设置：

```bash
python scripts/evaluation/images_to_video.py
python scripts/analysis/plot_s3_longitudinal_bias.py
```

不要用测试集反复选择阈值或修改模型；若需要选择 score threshold，应以验证集结果为依据。

## 7. 常见问题

- `PackagesNotFoundError` 或在 PowerShell 找不到 Linux 包：请在 Linux/WSL Ubuntu 中安装，不要用 Windows 原生 Conda 创建此 Linux 环境。
- `torch`/`torchvision` 版本冲突：两者必须是配套版本；离线安装时只使用随包提供的安装脚本，不要混装其他 CUDA 索引中的版本。
- `MMCV incompatible`：项目要求 `mmcv-full==1.7.0`；不要升级为 1.7.2 或 MMCV 2.x。
- `numpy` 版本冲突：项目固定 `numpy==1.26.4`，不要升级到 2.x。
- `libcudnn.so`、`No CUDA GPUs are available`：分别检查 PyTorch/CUDA 运行库和驱动/WSL GPU 透传，运行 `nvidia-smi` 确认设备可见。
- 自定义算子或 MMCV 编译失败：先检查 `nvcc --version`、`gcc --version`、`g++ --version` 与 Torch CUDA 版本，再查看编译日志第一条真正的 `error:`；最后的 `ninja` 失败通常只是汇总信息。
- 找不到数据或帧数量异常：检查 JSON 中路径（相对路径基于配置文件）、帧号 offset、图片/JSON 命名模板、CSV 表头和三类数据的帧对应关系。

遇到问题时，保留完整命令、第一条错误及其前后日志、`nvidia-smi` 和 `python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"` 输出，便于定位。
